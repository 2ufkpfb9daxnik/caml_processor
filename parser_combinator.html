4-2. 字句解析器および構文解析器の自作

文字列から抽象構文木（AST）を生成する関数 parse があれば、わざわざ If (Eq(IntLit 2, IntLit 1), ...) のように複雑な exp 型のデータを手で書く必要がなくなり、大変便利である。これまでは ocamllex や ocamlyacc などの専用ツールを利用してこれを実現することを前提としてきたが、プログラミング言語の処理系の全容を真に理解するためには、これらを自作することが有効である。

構文解析器をゼロから自作すると聞くと、複雑で難解なプログラムになると思うかもしれない。しかし、OCamlのような関数型言語の仕組みをうまく活用すれば、美しく、簡潔で、わかりやすいプログラムとして実装することができる。

文字列から構文木を組み立てる処理は、大きく分けて字句解析と構文解析の2つの役割からなる。複雑な処理に見えるが、これらを実装するには、いきなり全体を書こうとするのではなく、ごく小さな処理の単位に問題を分割し、それらを組み合わせていく手法をとればよい。

  • 字句解析器 (lexer)：入力として文字のリストを受け取り、意味のある塊（トークン）と、まだ処理していない残りの文字列のペアを出力する。
  • 構文解析器 (parser)：字句解析の結果を利用して、完成した構文木（AST）と、まだ処理していない残りの文字列のペアを出力する。

字句解析器 (lexer) の実装方針

字句解析器は、入力された文字列をトークン（単語に相当する意味の塊）の列に分割する役割を持つ。これを実装するためには、以下のように小さな関数へと問題を分割する。
  • 入力文字列を文字のリストに変換する: 外部から与えられるソースコードを、先頭の文字と未処理の残りに分けて扱いやすい char list 型へ変換する。
  • 1文字を処理する: 入力された文字列の先頭から、条件に合う「1文字」だけを読み取る機能を作る。
  • 不要な文字を読み飛ばす: 上記を利用して、スペースや改行などの意味を持たない空白文字を連続して読み飛ばす機能を作る。
  • 意味のある塊（トークン）を切り出す: 数字が連続していれば束ねて「整数」に変換し、+ や * といった文字が来れば「特定のキーワードや記号」として認識して切り出す機能を作る。

1. 字句解析器（lexer）の実装：最小単位からの組み立て

字句解析器は、入力された文字のリスト（char list）を受け取り、意味のあるデータ（トークン）と残りの文字列のペアを返す。ここではAST（構文木）の構築はまだ行わず、あくまで「文字の列からトークンを切り出す」ことだけに専念する。

最初に、対象とするミニOCaml言語の式の構文を限定して、「整数の定数」と「足し算」「かけ算」だけを持つ式とし、これに対する字句解析および構文解析を考える。したがって、現段階の処理系には if 式や真理値定数などは含まないことに注意してほしい。まずはこの限定された構文に対して「文字列から構文木を完全に構築する」という一連の流れを完成させる。それが完了したその後から、徐々に機能を足していくことにする。

これを簡単に実装するために、先ほどの3つの小さな関数（サブ目標）を、さらに具体的な「ミニ目標」に分割してコードを記述していく。

サブ目標 A: 入力文字列を文字のリストに変換する

字句解析器が受け取る元のソースコードは、"1 + 2" のような string 型の文字列である。OCamlでは、String.get s i または s.[i] を使うと、文字列 s の i 番目の文字を取り出せる。

String.get "abc" 0
(* 結果: 'a' *)

"abc".[0]
(* 結果: 'a' *)

ただし、添字を使って字句解析を進める場合は、「現在何文字目まで読んだか」を表す位置を別に管理する必要がある。本章では、先頭から文字を読み取るたびに、未処理の残りをそのまま次の処理へ渡せるよう、入力を char list として扱う。

文字のリストであれば、c :: cs というパターンによって、先頭の1文字 c と、それ以外の未処理部分 cs を直接分けることができる。

match input with
| c :: cs ->
    (* c  は先頭の1文字
       cs はまだ読んでいない残りの文字リスト *)
    ...
| [] ->
    (* 入力をすべて読み終えた *)
    ...
  • ミニ目標 A-1: パーサの入力型を定義する
    本章でパーサへ渡す入力を char list とし、input という型名を付ける。
  • ミニ目標 A-2: 文字列を文字のリストへ変換する (chars_of_string)
    String.to_seq で文字列を文字の列へ変換し、List.of_seq でその列をリストに変換する。 
(* ミニ目標 A-1: パーサが受け取る入力の型 *)
type input = char list

(* ミニ目標 A-2: string を char list に変換する *)
(* chars_of_string : string -> input *)
let chars_of_string s =
  List.of_seq (String.to_seq s)

例えば、chars_of_string "12+3" の結果は次のようになる。

['1'; '2'; '+'; '3']

以後の字句解析器は、この文字リストを入力として受け取る。文字列から文字を読むための特別な入出力関数をその都度呼ぶのではなく、リストに対するパターンマッチを用いて、先頭の文字と残りの入力を取り出していく。

サブ目標 B: 1文字を処理する

「入力された文字列の先頭から、条件に合う1文字だけを読み取る」という処理は、以下の2つのミニ目標を組み合わせることで実現できる。
  • ミニ目標 B-1: 条件を満たす1文字だけを読む (satisfy)
    入力の先頭の1文字を調べ、与えられた条件関数 cond を満たす場合のみ、その文字と残りのリストを返す関数を作る。
  • ミニ目標 B-2: 特定の1文字を読む (char_p)
    ミニ目標 B-1 を利用し、「指定した文字 c と一致するか」という条件を与えることで、特定の1文字を読み取る関数を作る。 
(* ミニ目標 B-1: 条件を満たす1文字を読む *)
(* 入力: 条件関数 cond (char -> bool) と 文字リスト (input) *)
(* 出力: 条件を満たせば Some(読み取った文字, 残りの文字リスト)、満たさなければ None *)
(* satisfy : (char -> bool) -> input -> (char * input) option *)
let satisfy cond input =
  match input with
  | c :: cs when cond c -> Some (c, cs)
  | _ -> None

(* ミニ目標 B-2: 特定の1文字を読む *)
(* 入力: 読み取りたい文字 c と 文字リスト (input) *)
(* 出力: 先頭が c なら Some(c, 残りの文字リスト)、それ以外なら None *)
(* char_p : char -> input -> (char * input) option *)
let char_p c input =
  satisfy (fun x -> x = c) input
satisfy は汎用的な関数である。引数として「文字を受け取って真偽値を返す関数（cond）」を受け取るため、後述の「数字かどうか」の判定など、様々な用途に使い回すことができる。

サブ目標 C: 不要な文字を読み飛ばす

プログラムの意味に影響を与えない空白文字（スペースや改行など）を処理する。これはこれ以上分割せず、1つの関数として実装する。
  • ミニ目標 C-1: 空白文字の読み飛ばし (skip_spaces)
    入力の先頭が空白文字であれば、それを捨てて再帰的に次の文字を調べる。空白以外の文字が現れた時点で、その残りのリストをそのまま返す。 
(* ミニ目標 C-1: 空白の読み飛ばし *)
(* 入力: 文字リスト (input) *)
(* 出力: 先頭の連続する空白を取り除いた残りの文字リスト *)
(* skip_spaces : input -> input *)
let rec skip_spaces input =
  match input with
  (* ' 'はスペース, '\t'はタブ, '\n'は改行, '\r'はキャリッジリターン(Windows等の改行コードの一部)を表す *)
  | c :: cs when c = ' ' || c = '\t' || c = '\n' || c = '\r' ->
      skip_spaces cs (* 空白だったので、残りのリスト cs に対して再帰的に処理を続ける *)
  | _ -> input       (* 空白以外の文字が来たら、あるいはリストが空になったら、現在のリストをそのまま返す *)

サブ目標 D: 意味のある塊（トークン）を切り出す

最後に、「数字が連続していれば束ねて整数に変換し、特定の記号が来ればキーワードとして切り出す」という処理を実装する。これは以下の2つのミニ目標からなる。
  • ミニ目標 D-1: 整数の切り出し (int_p)
    数字（'0'〜'9'）が連続している間だけ文字を読み進め、それらを束ねて OCaml の int 型に変換して返す。
  • ミニ目標 D-2: キーワードや記号の切り出し (keyword_p)
    + や * といった指定された文字列（文字のリスト）と、入力の先頭が完全に一致するかを順番に確認し、一致すればその文字列をトークンとして返す。 
(* ミニ目標 D-1: 整数の切り出し *)
(* 入力: 文字リスト (input) *)
(* 出力: 数字が1つ以上あれば Some(変換された整数, 残りの文字リスト)、なければ None *)
(* int_p : input -> (int * input) option *)
let int_p input =
  (* is_digit : char -> bool *)
  let is_digit c = c >= '0' && c <= '9' in
  
  (* 補助関数 read_digits: 数字が続く限り、acc（アキュムレータ）に文字を溜め込む *)
  (* read_digits : input -> char list -> char list * input *)
  let rec read_digits chars acc =
    match chars with
    | c :: cs when is_digit c -> read_digits cs (c :: acc)
    | _ -> (List.rev acc, chars)
  in
  
  match read_digits input [] with
  | ([], _) -> None (* アキュムレータが空 = 最初から数字が一つもなかった場合 *)
  | (digits, rest) ->
      (* 文字のリストを文字列(string)に変換してから、整数(int)に変換する *)
      let str = String.of_seq (List.to_seq digits) in
      Some (int_of_string str, rest)
ここで登場した acc（アキュムレータ）とは、再帰呼び出しの中で「計算の途中結果を蓄積しておくための引数」のことである。 たとえば入力が ['1'; '2'; '+'] だった場合、read_digits は以下のように動作する。
  1. read_digits ['1'; '2'; '+'] [] が呼ばれる。
  2. '1' は数字なので、acc に追加して再帰: read_digits ['2'; '+'] ['1']
  3. '2' は数字なので、acc に追加して再帰: read_digits ['+'] ['2'; '1']
  4. '+' は数字ではないので終了。結果として (['2'; '1'], ['+']) が返る。
最後に List.rev を使って acc を逆順（['1'; '2']）に戻すことで、正しい数字の並びを取得している。 
(* ミニ目標 D-2: 特定のキーワードや記号の切り出し *)
(* 入力: 探したいキーワード kw (string) と 文字リスト (input) *)
(* 出力: 先頭が kw と一致すれば Some(kw, 残りの文字リスト)、しなければ None *)
(* keyword_p : string -> input -> (string * input) option *)
let keyword_p kw input =
  
  (* 補助関数 check_chars: targetの文字リストと、現在の入力charsが順番に一致するか確認する *)
  (* check_chars : input -> char list -> (string * input) option *)
  let rec check_chars chars target =
    match target with
    | [] -> Some (kw, chars) (* 探したい文字(target)を全て読み終えたら、一致したとみなして成功 *)
    | t :: ts ->
        (match char_p t chars with
         | Some (_, rest) -> check_chars rest ts (* 1文字一致したので、残りを再帰的に確認する *)
         | None -> None) (* 途中で一致しない文字があったら失敗 *)
  in
  
  (* 探したい文字列 kw を文字のリストに変換してから check_chars に渡す *)
  check_chars input (List.of_seq (String.to_seq kw))
ここまでに定義した関数群だけで、eval1 で扱う構文（整数、+、*）を文字リストからトークンとして切り出すための部品はすべて揃っている。この後作成する構文解析器（parser）は、これらの関数を呼び出して結果を繋ぎ合わせるだけで構成できる。

構文解析器 (parser) の実装方針

構文解析器は、字句解析の機能を利用してトークンの列を読み込み、文法の定義に応じた木（構文木、すなわち exp 型のデータ）を組み立てる。これも字句解析と同様に、以下のように要素ごとに処理を分割できる。

（※前述の通り、現段階では 整数、足し算、かけ算のみを対象とし、if 式や真理値などの複合的な構文は後から追加していく。）

  • 式の基本要素を組み立てる: 整数など、それ以上分割できない最小単位の式を読み取って構文木（IntLit）にする機能を作る。
  • 演算式を組み立てる: + や * などの演算子を読み取り、その左辺の構文木と右辺の構文木を繋ぎ合わせて、1つの大きな構文木（Plus や Times）にする機能を作る。
このように、「文字列を受け取り、目的のデータ（トークンや構文木）を読み取り、残りの文字列をペアにして返す」という共通の構造を持つ小さな関数（部品）をたくさん作り、それらを繋ぎ合わせていくことで、最終的に巨大な1つの構文解析器を構築することができる。

それでは、最も基本的な部品の作成から順番に見ていこう。

2. 構文解析器（parser）の実装：構文木の組み立て

字句解析の部品（int_p や keyword_p など）が揃ったので、これらを利用して構文解析器を作っていく。 ここでの目標は、入力された文字のリストから意味のあるトークンを読み取り、最終的に exp 型の「抽象構文木（AST）」を構築することである。

処理の優先順位（かけ算は足し算より先に計算するなど）を正しく反映させるため、構文解析もいくつかの「ミニ目標」に分割して順番に呼び出していく。

サブ目標 E: 式の基本要素を組み立てる

まずは、これ以上分割できない最小単位の式、今回の範囲では「整数」のみを、構文木に変換する関数を作る。

  • ミニ目標 E-1: 最小単位（整数リテラル）のパース (primary_expr)
    字句解析で作った int_p を呼び出して整数を読み取り、得られた整数 n を IntLit(n) という構文木で包んで返す。 
(* 出力の型定義: 成功すれば Some(構文木, 残りの文字列)、失敗すれば None *)
type 'a parser_result = ('a * input) option

(* ミニ目標 E-1: 最小単位のパース *)
(* 入力: 文字リスト (input) *)
(* 出力: 整数のASTが作れれば Some(IntLit n, 残りの文字リスト)、失敗すれば None *)
(* primary_expr : input -> (exp * input) option *)
let primary_expr input =
  let input_after_spaces = skip_spaces input in
  
  (* 字句解析器の int_p を呼び出して整数を読む *)
  match int_p input_after_spaces with
  | Some (n, rest) -> 
      (* 整数 n が読めたら、それを IntLit(n) という AST に変換して返す *)
      Some (IntLit n, rest)
  | None -> None
この関数により、たとえば [' '; '4'; '2'] という入力を与えると、Some (IntLit 42, []) が返ってくるようになる。これが構文木の「葉（一番端の部分）」となる。

      in
      parse_rest e1 rest1

(* 足し算のパース（構造はかけ算と全く同じ） *)
(* plus_expr : input -> (exp * input) option *)
let rec plus_expr input =
  (* 左辺の読み取り（かけ算を含む可能性があるので times_expr を呼ぶ） *)
  match times_expr input with
  | None -> None
  | Some (e1, rest1) ->
      (* parse_rest : exp -> input -> (exp * input) option *)
      let rec parse_rest current_e current_rest =
        let r = skip_spaces current_rest in
        (* 演算子(+)の確認と右辺(times_expr)の読み取り *)
        match keyword_p "+" r with
        | Some (_, rest2) ->
            (match times_expr rest2 with
             | Some (e2, rest3) -> 
                 let new_e = Plus (current_e, e2) in
                 parse_rest new_e rest3
             | None -> Some (current_e, current_rest))
        | None -> Some (current_e, current_rest)
      in
      parse_rest e1 rest1

サブ目標 G: エントリーポイントの作成

最後に、文字列を受け取って最終的な AST を一つだけ返す便利な関数を作る。
  • ミニ目標 G-1: 全体を統括する parse 関数の作成
    文字列を char list に変換し、一番優先順位の低い plus_expr を呼び出す。成功した場合、文字列が最後まで消費されているかを確認する。 
(* ミニ目標 G-1: 構文解析の実行関数 *)
(* 入力: ソースコードの文字列 (string) *)
(* 出力: 完成した構文木 (exp) *)
(* parse : string -> exp *)
let parse s =
  let chars = chars_of_string s in
  
  (* 式全体のパースを開始する（一番優先度が低い plus_expr から呼ぶ） *)
  match plus_expr chars with
  | Some (ast, rest) -> 
      (* パース成功。最後に残った空白を読み飛ばす *)
      let final_rest = skip_spaces rest in
      
      if final_rest = [] then 
        ast (* 残っていなければ、完成したASTを返す *)
      else 
        failwith "Parse Error: 式の後ろに余分な文字があります"
        
  | None -> 
      failwith "Parse Error: 構文解析に失敗しました"

これで、文字列からトークンを切り出し、それらを組み合わせて構文木（AST）を作り上げる一連の処理系が完全に動作するようになった。

手元の環境で parse "1 + 2 * 3" と入力すると、Plus (IntLit 1, Times (IntLit 2, IntLit 3)) という構文木が自動で生成される。

サブ目標 I: 字句解析器（lexer）の確認

新しい構文を読み取るにあたり、字句解析器に新しい関数を追加する必要があるだろうか？ 実は、追加する必要はない。 すでに作成した keyword_p は、「指定した文字列と一致するか」を判定する汎用的な関数である。したがって、keyword_p "true" や keyword_p "=" と呼び出すだけで、真理値や比較演算子も独立したトークンとして簡単に切り出すことができる。これが、問題を小さな関数に分割して組み立てる手法（モジュール化という）の大きな利点である。

サブ目標 J: 構文解析器の基本要素（葉）の拡張

字句解析の準備ができているので、さっそく構文解析器を拡張する。まずは一番優先度が高く、ASTの末端（葉）となる primary_expr に真理値を追加する。
  • ミニ目標 J-1: true と false のパース
    入力文字列が整数でなかった場合、次に "true" であるか試し、それも失敗したら "false" であるか試すように match 式をネスト（入れ子）にして処理を繋ぐ。 
(* ミニ目標 J-1: 最小単位（整数と真理値）のパース *)
(* primary_expr : input -> (exp * input) option *)
let rec primary_expr input =
  let input = skip_spaces input in
  
  (* 1. まず整数か試す *)
  match int_p input with
  | Some (n, rest) -> Some (IntLit n, rest)
  | None ->
      
      (* 2. 整数でなければ "true" か試す *)
      (match keyword_p "true" input with
       | Some (_, rest) -> Some (BoolLit true, rest)
       | None ->
           
           (* 3. "true" でもなければ "false" か試す *)
           (match keyword_p "false" input with
            | Some (_, rest) -> Some (BoolLit false, rest)
            | None -> None)) (* 全てに失敗したら None を返す *)

サブ目標 K: 比較演算式のパース（新しい優先順位の追加）

次に、比較演算子 = のパース処理を追加する。 ここで文法の「優先順位」について考えてみよう。1 + 2 = 3 という式は、(1 + 2) = 3 と解釈されるべきであり、1 + (2 = 3) と解釈されてはならない。 つまり、「比較演算子は、足し算よりも優先順位が低い」ということになる。 これを実装に落とし込むには、これまでエントリーポイントだった plus_expr をさらに外側から呼び出す新しい関数 comp_expr を作ればよい。
  • ミニ目標 K-1: 左辺（足し算式）の読み取り
    比較演算の構成要素は、より優先度の高い plus_expr であるはずなので、まずはこれを呼び出して左辺（e1）を取得する。
  • ミニ目標 K-2: = の確認と右辺の読み取り
    = があるか確認し、あれば右辺の plus_expr を読み取って Eq の構文木を作る。
  • ミニ目標 K-3: 演算子がない場合の処理
    = が存在しなければ、比較式ではない（単なる足し算や整数の式である）とみなし、左辺 e1 をそのまま返す。 
(* ミニ目標 K: 比較演算のパース *)
(* （※比較演算は 1 = 2 = 3 のように連続しないものと仮定し、アキュムレータを用いたループは行わない） *)
(* comp_expr : input -> (exp * input) option *)
let rec comp_expr input =
  
  (* ミニ目標 K-1: 左辺の読み取り（plus_expr を呼ぶ） *)
  match plus_expr input with
  | None -> None
  | Some (e1, rest1) ->
      let r = skip_spaces rest1 in
      
      (* ミニ目標 K-2: "=" の確認と右辺の読み取り *)
      (match keyword_p "=" r with
       | Some (_, rest2) ->
           (match plus_expr rest2 with
            | Some (e2, rest3) -> Some (Eq (e1, e2), rest3)
            | None -> Some (e1, rest1))
       
       | None ->
           (* ミニ目標 K-3: "=" が無ければ、左辺をそのまま返す *)
           Some (e1, rest1))

サブ目標 L: エントリーポイントの更新

最後に、文字列を受け取ってパースを開始する parse 関数を更新する。一番優先順位の低い関数が plus_expr から comp_expr に変わったため、呼び出し元を変更するだけでよい。
  • ミニ目標 L-1: parse 関数の呼び出し先変更
    match plus_expr chars with となっていた部分を match comp_expr chars with に書き換える。 
(* ミニ目標 L-1: エントリーポイントの更新 *)
(* parse : string -> exp *)
let parse s =
  let chars = chars_of_string s in
  
  (* 一番優先順位の低い comp_expr からパースを開始する *)
  match comp_expr chars with
  | Some (ast, rest) -> 
      let final_rest = skip_spaces rest in
      if final_rest = [] then ast
      else failwith "Parse Error: 式の後ろに余分な文字があります"
  | None -> failwith "Parse Error"
これで、真理値と等価演算子（=）が正しくパースできるようになった。

  • ミニ目標 N-2: then と真の場合の式 (e2) の読み取り
    条件式 e1 の後ろの空白を読み飛ばし、"then" が続くか確認する。一致すれば、それに続く式（e2）をパースする。
  • ミニ目標 N-3: else と偽の場合の式 (e3) の読み取りおよびAST構築

  • ミニ目標 N-4: if で始まらない場合の処理

  | Some (_, rest1) ->
      (match if_expr rest1 with
       | Some (e1, rest2) ->

            | Some (_, rest3) ->
                (match if_expr rest3 with
                 | Some (e2, rest4) ->
                     
                     (* ミニ目標 N-3: "else" と偽の場合の式(e3)の読み取りおよびAST構築 *)
                     let r3 = skip_spaces rest4 in
                     (match keyword_p "else" r3 with
                      | Some (_, rest5) ->
                          (match if_expr rest5 with
                           | Some (e3, rest6) -> 
                               (* 全て揃ったので If の構文木を作って返す *)
                               Some (If (e1, e2, e3), rest6)
                           | None -> None)
                      | None -> None)
                 | None -> None)
            | None -> None)
       | None -> None)
       
  | None ->
      (* ミニ目標 N-4: "if" で始まらない場合は comp_expr に任せる *)
      comp_expr input

サブ目標 P: 状態の受け渡しをまとめる関数 bind の定義

if_expr の実装に何度も現れていたのは、「前のパースが成功したら、その結果（構文木と残りの文字列）を使って、次のパースを行う。失敗したら None を返す」という処理である。 最初に思いつくのは、この共通の処理をまとめて1つの関数として定義することである。ここでは、処理を結びつけるという意味で bind という名前の関数とする。
  • ミニ目標 P-1: bind 関数の定義
    パーサ p と、次の処理を行う関数 f を受け取り、それらを繋げて新しいパーサを作る関数を定義する。
  • ミニ目標 P-2: return 関数の定義
    単に値（構文木など）を受け取り、それを Some(値, 残りの文字列) の形に包んで成功を返すだけの小さな関数を用意しておく。 
(* ミニ目標 P-1: 状態の受け渡しとエラー処理を隠蔽する高階関数 *)
(* p: 最初に実行するパーサ *)
(* f: pの結果を受け取り、次に実行するパーサを返す「関数」 *)
(* bind : (input -> ('a * input) option) -> ('a -> input -> ('b * input) option) -> input -> ('b * input) option *)
let bind p f =
  fun input ->
    match p input with
    | None -> None
    | Some (v, rest) -> f v rest

(* ミニ目標 P-2: 常に成功して値を返すだけの小さなパーサ *)
(* return : 'a -> input -> ('a * input) option *)
let return v =
  fun input -> Some (v, input)
ここでわかるように、bind の第2引数 f は、関数である。p が成功した場合だけ、読み取った値 v を f に渡して次のパースへ進む。一方、p が失敗した場合は、後続の処理を実行せずに None を返す。

サブ目標 Q: bind 関数による共通処理の隠蔽

作成した bind を使うと、これまで繰り返し記述していた match と、失敗時に None を返す処理を隠すことができる。
  • ミニ目標 Q-1: bind によるパース処理の連結
    if、条件式、then、真の場合の式、else、偽の場合の式を、bind を使って順番に連結する。 
(* ミニ目標 Q-1: bind 関数を用いて書き直した if_expr *)
(* if_expr : input -> (exp * input) option *)
let rec if_expr input =
  bind (token (keyword_p "if")) (fun _ ->
    bind if_expr (fun e1 ->
      bind (token (keyword_p "then")) (fun _ ->
        bind if_expr (fun e2 ->
          bind (token (keyword_p "else")) (fun _ ->
            bind if_expr (fun e3 ->
              return (If (e1, e2, e3))
            )
          )
        )
      )
    )
  ) input

このように、パース失敗時に None を返す処理と、残りの入力を次のパーサへ渡す処理は、bind の中に隠蔽された。そのため、以前の実装にあった match ... with の繰り返しはなくなっている。

しかし、if 式のように複数のパーサを順番に実行すると、今度は bind と fun ... -> の入れ子が深くなる。処理そのものは、if、条件式、then、真の場合の式、else、偽の場合の式を順番に読んでいるだけだが、コードの右側へ向かって括弧が重なり、処理の流れを追いにくい。

つまり、bind によって「失敗の処理」と「残りの入力の受け渡し」は共通化できたが、通常の関数呼び出しとして書く限り、連続する処理の見た目にはまだ改善の余地がある。そこで次に、同じ bind を上から下へ記述するための束縛演算子 let* を導入する。

サブ目標 R: 束縛演算子 let* による可読性の改善

OCaml 4.08以降には、bind ... (fun x -> ...) のような処理を、通常の let に近い形で記述するための「束縛演算子 (Binding operators)」という構文が用意されている。

let* の意味があらかじめ固定されているわけではない。今回は、次のように let* を bind として定義することで、パーサを順番に連結するために使用する。

  • ミニ目標 R-1: 束縛演算子 let* の定義と、空白を自動で飛ばす工夫
    bind 関数を let* として利用できるように定義する。さらに、キーワードなどを読んだ直後に「自動で空白を読み飛ばす」ラッパー関数 token を用意する。
  • ミニ目標 R-2: let* を用いた if_expr の完成
    let* と token を使い、if 式のパースを上から下へ読める形で記述する。 
(* ミニ目標 R-1: bind を let* として使用するための定義 *)
(* let* : (input -> ('a * input) option) -> ('a -> input -> ('b * input) option) -> input -> ('b * input) option *)
let ( let* ) = bind

(* 任意のパーサ p を実行した直後に、空白をスキップするラッパー *)
(* token : (input -> ('a * input) option) -> input -> ('a * input) option *)
let token p =
  let* v = p in
  fun input -> Some (v, skip_spaces input)

(* ミニ目標 R-2: let* を用いた if_expr *)
(* if_expr : input -> (exp * input) option *)
let rec if_expr input =
  (let* _  = token (keyword_p "if") in
   let* e1 = if_expr in
   let* _  = token (keyword_p "then") in
   let* e2 = if_expr in
   let* _  = token (keyword_p "else") in
   let* e3 = if_expr in
   return (If (e1, e2, e3)))
  input

let* x = p in e は、定義された演算子関数 ( let* ) に、パーサ p と関数 fun x -> e を渡す形に解釈される。今回は ( let* ) を bind として定義しているため、次の2つは同じ意味になる。

let* x = p in
q x
bind p (fun x ->
  q x)
冗長だった match と None が消えただけでなく、文法 if e1 then e2 else e3 に対応する処理を上から下へ順番に記述できるようになった。以後は、この let* を標準として実装を進めていこう。

独自の中置演算子による書き方（補足）

OCamlでは、記号からなる関数を独自の中置演算子として定義することもできる。例えば、bind を次のように >>= という演算子へ割り当てられる。

(* >>= : (input -> ('a * input) option) -> ('a -> input -> ('b * input) option) -> input -> ('b * input) option *)
let ( >>= ) = bind

このとき、

p >>= f

という式は、

( >>= ) p f
(* つまり bind p f と同じ *)

として解釈される。したがって、let* を使わず、次のように処理を繋ぐ書き方も可能である。

p >>= fun x ->
q x

この書き方もパーサコンビネータやモナドを扱うコードで用いられるが、本章では、通常の変数束縛に近い見た目で読める let* を使用する。

発展的な話題：モナドと副作用の隠蔽

実は、今回定義した bind と return の組み合わせは、関数型言語の世界で「モナド (Monad)」と呼ばれる重要な構造に対応している（正確には、モナドとして扱うには「モナド則」と呼ばれる規則を満たす必要がある）。

関数型言語では、変数の書き換えや、失敗（エラー）の発生、状態の変更といった副作用的な要素を、純粋な関数の組合せとして整理して扱うことがある。しかし、構文解析のように「残りの文字列という状態を引き回す」「途中でパースに失敗するかもしれない」という処理をそのまま記述すると、我々が直面したような match の深いネストに陥ってしまう。

bind は、この「状態の伝播」や「失敗の処理」を共通化し、個々の構文解析処理から隠蔽する。let* は、その bind の連鎖を読みやすく記述するための構文である。「モナド」という言葉は難解に聞こえるかもしれないが、if_expr を書き換えた過程を見ると、その役割を具体的に理解できる。

6. 他の構文のコンビネータ化と次章への準備

if 式以外の構文解析処理（整数、足し算、比較）も、この let* を使ったパーサコンビネータのスタイルで書き直してみよう。

ここでは新しく、「左側のパーサを試し、失敗したら右側のパーサを試す」というバックトラック処理を隠蔽するコンビネータ <|> (alt) を導入する。これを使うと match ... with | None -> ... という分岐を消すことができる。

(* 選択実行の関数 (alt) *)
(* alt : (input -> ('a * input) option) -> (input -> ('a * input) option) -> input -> ('a * input) option *)
let alt p1 p2 =
  fun input ->
    match p1 input with
    | Some _ as res -> res
    | None -> p2 input

(* 中置演算子としての定義 *)
(* <|> : (input -> ('a * input) option) -> (input -> ('a * input) option) -> input -> ('a * input) option *)
let ( <|> ) = alt

例として、一番単純な整数（primary_expr）、足し算（plus_expr）、および等価演算子（comp_expr）を let* と <|> を使って書き直したコードを以下に示す。以前の match だらけのコードと見比べると、その読みやすさは歴然である。

（※ let* の範囲を明確にするため、<|> と組み合わせる際は (let* ... in ...) <|> return ... のように括弧でくくる点に注意すること。）

(* 例1: 最小単位（整数のみ）のパース *)
(* primary_expr : input -> (exp * input) option *)
let rec primary_expr input =
  (let* n = token int_p in
   return (IntLit n))
  input

(* 例2: 足し算のパース *)
(* plus_expr : input -> (exp * input) option *)
let rec plus_expr input =
  (* 左辺をパース *)
  (let* e1 = times_expr in
   
   (* アキュムレータを用いた再帰関数も、let* と <|> で書ける *)
   (* parse_rest : exp -> input -> (exp * input) option *)
   let rec parse_rest current_e =
     (let* _  = token (keyword_p "+") in
      let* e2 = times_expr in
      let new_e = Plus (current_e, e2) in
      parse_rest new_e)
     <|> return current_e  (* "+" が無ければ(失敗したら) current_e を返す *)
   in
   parse_rest e1)
  input

(* 例3: 比較演算(=)のパース *)
(* comp_expr : input -> (exp * input) option *)
let rec comp_expr input =
  (let* e1 = plus_expr in
   
   (let* _  = token (keyword_p "=") in
    let* e2 = plus_expr in
    return (Eq (e1, e2)))
   <|> return e1) (* "=" が無ければ左辺 e1 をそのまま返す *)
  input

課題 4-2-5 (パーサコンビネータへの書き換え)

上記の例を参考に、まだコンビネータのスタイルに書き換えられていない以下の機能について、let* と token（および <|>）を用いてコードを書き換えなさい。
  1. 真理値の追加: primary_expr を拡張し、整数のパースに失敗したら true、それも失敗したら false を試すように <|> で繋ぎなさい。
  2. 四則演算の完成: plus_expr と times_expr に、それぞれ引き算（-）と割り算（/）の処理を追加しなさい（+ のパースに失敗したら - を試すようにする）。
  3. 比較演算の完成: comp_expr に、< と > の処理を追加しなさい。
書き換え後も、これまでに試したすべてのテスト・データ（if 0 < 10 then ... など）が正しくパースできることを確認すること。

7. 変数と let 式の追加：識別子と予約語の分離

次は、プログラム言語において基本となる「変数」と、それを束縛する「let 式」をパーサに追加する。 対象とする構文は let x = e1 in e2 （式 e1 の評価結果を変数 x に束縛し、式 e2 を評価する）と、変数 x 自身である。 この追加において注意すべき点は、字句解析におけるキーワード（予約語）と変数名の衝突である。例えば、if という文字列が変数名として扱われると、意図した通りにパースできなくなる。この問題を解決する手順を含め、これまでと同様に全体をサブ目標に分割して実装を進める。
  • サブ目標 S: 抽象構文木（AST）の拡張
    変数と let 式を表現できるように、exp 型を拡張する。
  • サブ目標 T: 字句解析器の拡張（識別子と予約語の分離）
    変数名として使える文字列（識別子）を切り出しつつ、それが if や let などの「予約語」でないことを確認するパーサを作成する。
  • サブ目標 U: 構文解析器の基本要素（葉）の拡張
    ASTの末端となる primary_expr を拡張し、変数をパースできるようにする。
  • サブ目標 V: let 式のパースとエントリーポイントの統合
    let 式のパーサを作成し、優先順位の低いトップレベルの式として if 式と並列にパースできるように全体を統合する。
それでは、それぞれのサブ目標について具体的な実装を見ていこう。

サブ目標 S: 抽象構文木（AST）の拡張

新しく追加する要素を表現できるように exp 型を拡張する。
  • ミニ目標 S-1: Var と Let の追加
    変数を表す Var of string と、let 式を表す Let of string * exp * exp を追加する。 
(* ミニ目標 S-1: ASTの拡張 *)
type exp =
  | IntLit of int
  | BoolLit of bool
  | Plus of exp * exp
  | Times of exp * exp
  | Eq of exp * exp
  | Lt of exp * exp
  | If of exp * exp * exp
  | Var of string                   (* 追加: 変数 x *)
  | Let of string * exp * exp       (* 追加: let x = e1 in e2 *)

サブ目標 T: 字句解析器の拡張（識別子と予約語の分離）

変数名（識別子）のパース処理を作成する。ここでは、変数名の最初の1文字はアルファベット、2文字目以降はアルファベット、数字、アンダースコア（_）の連続であるとする。
  • ミニ目標 T-1: 文字種の判定関数の用意
    文字がアルファベットであるか、あるいは英数字・アンダースコアであるかを判定する関数を用意する。
  • ミニ目標 T-2: 識別子の切り出しと予約語チェック (ident_p)
    先頭がアルファベットであれば文字の読み取りを開始し、続く英数字を束ねて文字列にする。その後、得られた文字列が予約語リストに含まれていないかチェックし、含まれていればパース失敗（None）とする。 
(* ミニ目標 T-1: 文字種の判定関数 *)
(* is_alpha : char -> bool *)
let is_alpha c = (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')
(* is_alnum : char -> bool *)
let is_alnum c = is_alpha c || (c >= '0' && c <= '9') || c = '_'

(* ミニ目標 T-2: 識別子（変数名）のパースと予約語チェック *)
(* 入力: 文字リスト (input) *)
(* 出力: 予約語以外の識別子が読めれば Some(変数名の文字列, 残りの文字リスト)、失敗すれば None *)
(* ident_p : input -> (string * input) option *)
let ident_p input =
  (* 英数字が続く限りアキュムレータ(acc)に溜め込む補助関数 *)
  (* read_alnum : input -> char list -> char list * input *)
  let rec read_alnum chars acc =
    match chars with
    | c :: cs when is_alnum c -> read_alnum cs (c :: acc)
    | _ -> (List.rev acc, chars)
  in
  
  match input with
  | c :: cs when is_alpha c -> 
      (* 1文字目がアルファベットだった場合のみ、残りの英数字を読み取る *)
      let (alnums, rest) = read_alnum cs [c] in
      let str = String.of_seq (List.to_seq alnums) in
      
      (* 予約語（キーワード）のリスト *)
      let reserved = ["let"; "in"; "if"; "then"; "else"; "true"; "false"] in
      
      if List.mem str reserved then
        None (* 読み取った文字列が予約語だった場合は、変数名としてはパース失敗とする *)
      else
        Some (str, rest) (* 予約語でなければ、変数名として返す *)
        
  | _ -> None
予約語を除外しないと、if true then 1 else 2 の if を変数として誤認し、正しくパースできなくなる。これは言語処理系において一般的な手順である。

サブ目標 U: 構文解析器の基本要素（葉）の拡張

字句解析の ident_p を利用し、ASTの末端となる primary_expr を拡張して変数をパースできるようにする。前節の方針通り、let* 構文と選択実行のコンビネータ <|> を組み合わせて記述する。
  • ミニ目標 U-1: 変数のパース処理の追加
    primary_expr の選択肢の末尾に、ident_p を用いたパース処理を追加する。 
(* ミニ目標 U-1: 変数(Var)の追加 *)
(* primary_expr : input -> (exp * input) option *)
let rec primary_expr input =
  ( (let* n = token int_p in return (IntLit n))
    <|> 
    (let* _ = token (keyword_p "true") in return (BoolLit true))
    <|> 
    (let* _ = token (keyword_p "false") in return (BoolLit false))
    <|> 
    (* 追加: 識別子が読めたら Var の構文木にする *)
    (let* x = token ident_p in return (Var x)) )
  input

サブ目標 V: let 式のパースとエントリーポイントの統合

次に let x = e1 in e2 をパースする処理を作成する。 let 式も if 式と同様に優先順位が低い構文である。そこで、構文解析のトップレベルの関数を expr という名前に統一し、let と if の両方を組み込む。
  • ミニ目標 V-1: let_expr の実装
    let* を使い、let、変数名（x）、=、式（e1）、in、式（e2）を順に読み取る。
  • ミニ目標 V-2: トップレベルの統合と parse の更新
    トップレベルのパーサ expr を新設し、let 式、if 式、比較式（comp_expr）の順にパースを試すようにする。 
(* 相互再帰的に呼び出すため、トップレベルを let rec expr ... and ... で繋ぐ *)

(* ミニ目標 V-2: トップレベルの統合パーサ *)
(* expr : input -> (exp * input) option *)
let rec expr input =
  (let_expr <|> if_expr <|> comp_expr) input

(* ミニ目標 V-1: let 式のパース *)
(* let_expr : input -> (exp * input) option *)
and let_expr input =
  (let* _  = token (keyword_p "let") in
   let* x  = token ident_p in          (* 変数名 x を読む *)
   let* _  = token (keyword_p "=") in
   let* e1 = expr in                   (* 束縛される式 e1 を読む *)
   let* _  = token (keyword_p "in") in
   let* e2 = expr in                   (* 続く本体の式 e2 を読む *)
   return (Let (x, e1, e2)))
  input

(* 以前作成した if_expr も、再帰呼び出し先を expr に変更する *)
(* if_expr : input -> (exp * input) option *)
and if_expr input =
  (let* _  = token (keyword_p "if") in
   let* e1 = expr in
   let* _  = token (keyword_p "then") in
   let* e2 = expr in
   let* _  = token (keyword_p "else") in
   let* e3 = expr in
   return (If (e1, e2, e3)))
  input

(* エントリーポイントの更新 *)
(* parse : string -> exp *)
let parse s =
  let chars = chars_of_string s in
  (* 全ての式の頂点である expr からパースを開始する *)
  match expr chars with
  | Some (ast, rest) -> 
      let final_rest = skip_spaces rest in
      if final_rest = [] then ast
      else failwith "Parse Error: 式の後ろに余分な文字があります"
  | None -> failwith "Parse Error"
（※ let_expr や if_expr の中で呼び出している再帰関数が comp_expr から expr に変わっている点に注意。これにより、let x = 1 in let y = 2 in x + y のように let 式の中にさらに let 式をネストさせることが可能になる。）

ここまでの構文解析器が扱うのは、整数・真理値・四則演算・比較演算・ if 式・変数・非再帰の let 式までである。 最終的にコンパイラ自身をこのミニOCaml言語で記述し、セルフホストを行うためには、 さらに次の構文要素を段階的に追加する必要がある。

  • 括弧で囲まれた式 
    (1 + 2) * 3
f (if b then x else y)
    演算子の通常の優先順位を括弧によって変更できるようにする。
  • Unitリテラル 
    ()
    値を返すことを目的としない処理や、入出力・配列更新などの結果を表すために使用する。
  • 文字リテラルと文字列リテラル 
    'a'
"hello"
"parse error"
    字句解析器が入力文字を調べたり、識別子やエラーメッセージを保持したりするために必要となる。 改行や引用符などを表すエスケープシーケンス （'\n'、"\""、"\\" など）も扱う必要がある。
  • 無名関数 
    fun x -> x + 1
fun x -> fun y -> x + y
    関数を値として表現するための基本構文である。 複数引数の関数は、単項関数を入れ子にした構文へ変換できる。
  • 関数適用 
    f x
f x y
f (g x)
    関数位置の式と引数の式を結合し、App の構文木を生成する。 f x y は通常、(f x) y と左結合に解釈する。 関数適用は、四則演算などよりも高い優先順位を持つ。
  • 名前付き関数定義の構文糖 
    let f x = e1 in e2
let add x y = x + y in add 1 2
    これは本質的には、次のような無名関数と let 式の組合せである。 
    let f = fun x -> e1 in e2

let add =
  fun x ->
    fun y ->
      x + y
in
add 1 2
    パース後の脱糖処理によって、基本的な Let と Fun に変換できる。
  • 部分適用と高階関数 
    let add x y = x + y in
let add10 = add 10 in
add10 5

let apply f x = f x in
apply (fun x -> x + 1) 10
    部分適用そのものに固有の表面構文はなく、通常の関数適用としてパースできる。 その意味は、関数値とクロージャを実装する段階で定める。
  • 再帰関数と相互再帰関数 
    let rec factorial n =
  if n = 0 then 1
  else n * factorial (n - 1)
in
factorial 5
    相互再帰を扱う場合は、and も追加する。 
    let rec even n =
  if n = 0 then true else odd (n - 1)
and odd n =
  if n = 0 then false else even (n - 1)
in
even 10
  • 組（タプル） 
    (1, true)
(x, y, z)
let (x, y) = pair in x + y
    コンパイラ内部で、複数の結果や位置情報などをまとめて扱うために利用できる。 ()、(e)、(e1, e2) を正しく区別する必要がある。
  • リスト 
    []
[1; 2; 3]
x :: xs
    トークン列、ASTの要素列、変数環境、命令列などを表現するために必要となる。 リストリテラルは、次のような :: と空リストの組合せへ脱糖できる。 
    [1; 2; 3]
=>
1 :: 2 :: 3 :: []
    :: は右結合として解析する。
  • 代数的データ型の宣言 
    type token =
  | TInt of int
  | TIdent of string
  | TPlus
  | TEOF

type expr =
  | IntLit of int
  | Plus of expr * expr
  | Var of string
    コンパイラ自身のトークン、構文木、型、中間表現などを定義するために必要となる。 そのため、式のパーサだけでなく、type 宣言と型式を解析するパーサも必要になる。
  • 型式 
    int
bool
string
expr
int * bool
expr list
int -> bool
    代数的データ型のコンストラクタが保持する値の型を記述するために必要となる。 関数型の -> は右結合、積型の * は式中の乗算とは別の型構文として扱う。
  • コンストラクタ式 
    TPlus
TInt 42
TIdent "name"
Plus (IntLit 1, IntLit 2)
    通常は、大文字で始まる名前をコンストラクタ、小文字で始まる名前を変数として区別する。 引数付きコンストラクタは、関数適用に近い構文として解析できる。
  • パターン 
    _
x
0
true
[]
x :: xs
(x, y)
TInt n
Plus (e1, e2)
    パターンは式とは別の構文カテゴリとして解析する。 最低限、ワイルドカード、変数、リテラル、空リスト、コンス、タプル、 コンストラクタの各パターンが必要となる。
  • パターンマッチ 
    match xs with
| [] -> 0
| x :: rest -> x
    字句解析器やコンパイラの各変換処理で、トークンやASTの種類に応じて処理を分岐するために必要となる。 複数の節を区切る | と、パターンと式を区切る -> を解析する必要がある。
  • 配列の生成・参照・更新 
    Array.make 10 0
a.(i)
a.(i) <- value
    可変バッファや表を効率よく扱うために必要となる。 配列参照 .( ) は高い優先順位を持つ後置構文として、 配列更新 <- は低い優先順位を持つ構文として扱う。 必要であれば配列リテラルも追加できる。 
    [|1; 2; 3|]
  • 逐次実行 
    e1; e2
    入出力や配列更新を順番に実行するために必要となる。 これは次のような束縛への構文糖として扱うこともできる。 
    let _ = e1 in e2
    ただし、リストや配列の要素区切りにも ; を使うため、 解析中の文脈を区別する必要がある。
  • 論理演算子 
    e1 && e2
e1 || e2
not e
    && と || は短絡評価を行う。 パース後に if 式へ脱糖することもできる。
  • 残りの比較演算子 
    e1 <> e2
e1 <= e2
e1 >= e2
    複数文字の演算子は、一文字の演算子より先に試す必要がある。 例えば <= を認識する前に < を確定してはならない。
  • コメント 
    (* comment *)

(* outer
   (* inner *)
   comment *)
    コンパイラ自身を現実的な規模で記述するにはコメントが必要となる。 OCamlと同様の入れ子可能なコメントを採用する場合は、コメント内部を再帰的に解析する。
  • トップレベル定義とプログラム全体 
    type token = ...

let tokenize source = ...

let rec parse_expr tokens = ...

let main = ...
    ここまで扱った let x = e1 in e2 は一つの式の内部にある局所束縛である。 コンパイラ全体を記述するには、inを伴わないトップレベルの type、let、let rec を複数並べた 「プログラム全体」を解析する必要がある。
  • ソース位置と構文エラー 
    parse error at line 3, column 12:
expected "then", but found "else"
    これは表面構文そのものではないが、セルフホストする構文解析器には重要である。 読み取った文字やトークンに行番号・列番号を付け、 単なる None ではなく、失敗位置と期待された構文を保持できるようにする必要がある。

これらを一度に追加する必要はない。まず無名関数・関数適用・再帰関数を追加し、 次に組・リスト・代数的データ型・パターンマッチを導入する。 その後、文字・文字列・配列・逐次実行・トップレベル定義を追加すると、 コンパイラ自身を記述できる程度の言語へ段階的に発展させることができる。

セルフホスト完成後の発展課題としては、let多相を含む型推論、型注釈、例外定義、 raise、try ... with、別コンパイル、モジュールなどが考えられる。
